# Fenext V1 安装与部署

适用版本：1.0.0。客户端与网页端共用服务；本次交付不包含已部署的公网服务。

## 交付文件

| 文件 | 用途 |
|---|---|
| Fenext-1.0.0-arm64-mac.zip | Apple 芯片 Mac 客户端，解压得到 Fenext.app |
| Fenext Setup 1.0.0.exe | Windows x64 安装程序，尚需 Windows 实机验收 |
| Fenext-Web-1.0.0.zip | 网页服务、前端构建、worker、部署配置和文档 |
| Fenext-Browser-1.0.0.zip | Chrome / Edge 共用的解压安装插件 |
| SHA256SUMS.txt / manifest.json | 文件完整性校验与版本清单 |

## 本机使用

V1 的主要测试场景是：电脑浏览器打开网页 → Fenext 插件提取当前页 → Fenext 客户端查看收集箱和知识库。客户端本身不读取浏览器标签页，测试完整流程还需要安装 Chrome / Edge 插件。

1. 安装 Node.js 24.16 或更新的 24.x 版本。解压网页端包，进入 `Fenext-Web-1.0.0` 文件夹。
2. 在该文件夹的终端运行：

   ```sh
   npm ci --omit=dev --ignore-scripts
   npm run web
   ```

3. 浏览器打开 `http://127.0.0.1:4310`。首次输入账号和至少 10 位密码，新账号自动注册。
4. 在设置中配置 AI 接口、模型和密钥；也可先收集，资料会等待配置。
5. 安装并打开客户端，它默认连接同一个本机服务。服务终端需继续运行。

无需启动 Vite 或使用 5173 端口；5173 是开发预览端口。网页端包默认数据目录为解压目录下的 `.local`，请勿删除或随升级覆盖它。

### macOS 客户端

将 ZIP 解压后的 `Fenext.app` 放入“应用程序”文件夹后打开。本次为未签名、未公证个人使用包；系统如拦截，请按系统提示自行决定是否允许。支持 Apple 芯片，未交付 Intel 安装包。

在本项目所在的 Apple 芯片 Mac 上测试，不用从网上重新下载：安装包是 `release/v1.0.0/Fenext-1.0.0-arm64-mac.zip`；也可以直接打开已解压的 `release/mac-arm64/Fenext.app`。客户端默认连接 `http://127.0.0.1:4310`，因此先确认本机服务正在运行。若看到连接失败，先启动服务，不要重新注册一个账号。

### 客户端 V1 实测流程

1. 打开 Fenext 客户端，使用已有的 Fenext 账号登录；在“来源与插件”确认“电脑浏览器当前页”的连接状态。
2. 如果尚未安装插件，按下方步骤在 Chrome 或 Edge 安装。到“接入与数据”生成接收凭证，在插件中填写服务地址 `http://127.0.0.1:4310` 与凭证，完成连接。已经连接的插件无需再次生成凭证。
3. 在浏览器打开一篇可正常阅读的网页。遇到网站验证，先在浏览器完成验证。点击工具栏中的 Fenext 插件，输入“想了解什么”，点击“提取当前页面”，核对内容后保存。
4. 回到客户端的“收集箱”查看新资料。同一来源再次提出不同问题时，应保留在该来源下的独立任务；处理完成后到“知识库”查看笔记。如显示等待配置，先在设置中填写可用的 AI 接口和密钥。
5. 若要在 Obsidian 查看笔记，点击客户端左下角头像 →“设置与同步”→“Obsidian 同步”→“连接 Obsidian”。确认当前知识库或选择其他知识库后，Fenext 会在库内建立 `Fenext/` 文件夹并立即同步。在 Obsidian 左侧打开 `Fenext/知识`，或点击客户端的“打开 Obsidian”。

只想检查客户端界面时，打开客户端并登录即可；要验证“浏览网页 → 提取 → 整理”的完整流程，需要服务和插件同时运行。

Obsidian 同步默认方向是 Fenext → Obsidian 库内的 `Fenext/` 文件夹。这个文件夹内由 Fenext 管理的笔记，后续在 Obsidian 修改正文也会同步回 Fenext；库内其他笔记不会自动导入。旧版绑定在知识库之外的普通目录会保留原文件，升级后需重新点击“连接 Obsidian”，旧文件不会自动删除或移动。

### Windows 客户端

运行安装程序，按安装向导完成。客户端为 x64 交叉构建，尚未在 Windows 实机验证，不能据此宣称 Windows 验收已完成。

### 连接已部署服务

客户端通过 `FENEXT_APP_URL` 指定服务地址，远程地址必须为 HTTPS。macOS 可在终端启动：

```sh
FENEXT_APP_URL=https://你的服务域名 /Applications/Fenext.app/Contents/MacOS/Fenext
```

Windows PowerShell：

```powershell
$env:FENEXT_APP_URL = "https://你的服务域名"
& "客户端实际安装路径\Fenext.exe"
```

切换前先从托盘或应用菜单完全退出原客户端。此环境变量方式不会自动修改系统快捷方式；正常双击仍连接默认本机地址。

## 服务器部署网页端

网页包可通过 Node.js 或 Docker 单节点部署。必须同时运行 API 和 worker。关闭客户端后继续处理，需要独立常驻服务器。

1. 解压到服务器目录，将 `.env.example` 复制为 `.env`。
2. 设置实际 HTTPS `APP_ORIGIN`、固定的 64 位十六进制 `MASTER_KEY`、强随机 `SETUP_TOKEN`。密钥只保存在私密配置和备份中。
3. 直接 Node.js 运行时，设置 `HOST=127.0.0.1`，让 HTTPS 反向代理转发到 4310；运行 `npm run web`，并通过系统进程管理器保持运行。
4. 或在网页包目录运行 `docker compose up -d --build`。API 和 worker 共用一个持久卷，4310 仅绑定服务器本机。
5. HTTPS 代理保留 `Origin`，访问域名创建首个账号时填写初始化令牌。后续账号以正常账号入口创建。
6. 配置备份，验证服务重启、任务处理及恢复。Docker 配置已提供，但当前机器未运行 Docker 守护进程，尚未完成容器运行验收。

不要将 SQLite 放在不支持所需锁语义的网络盘，也不要让多台服务器同时写同一数据库文件。数据库、上传内容和加密密钥必须持久保存。

## Chrome / Edge 插件

1. 在“来源与插件 → 电脑浏览器当前页”选择对应浏览器下载链接，或使用发布目录的插件 ZIP，解压保留 `extension` 文件夹。
2. 浏览器菜单打开扩展管理，启用开发者模式，选择“加载已解压的扩展程序”，选择 `extension` 文件夹。
3. 在 Fenext“接入与数据”生成接收凭证并填写备注，复制服务地址和凭证。
4. 打开浏览器工具栏的 Fenext 插件，填入两项信息，点击“连接并继续”。打开文章、完成网站验证后提取，核对正文并保存。

凭证长期有效，删除后立即失效；若遗失明文，生成新凭证替换，不能从列表再次查看旧明文。服务地址必须对应当前登录账户所在的服务。

## 升级、备份与回退

### 从预览版升级

1. 停止旧 API 和 worker，并从旧项目目录运行 `node scripts/backup.mjs` 创建一致性备份。
2. 将 V1 网页包解压到新目录，安装生产依赖。用原 `DATA_DIR` 的绝对路径和原 `MASTER_KEY`（或保留原数据目录中的 `master.key`），不要创建新空数据库替代已有资料。
3. 本机同样可在启动前设置 `DATA_DIR=/原数据目录绝对路径`。保留旧包和备份，启动 V1 服务后核对账号、收集箱、笔记和设置。
4. 旧有效接收凭证会转为长期有效；已过期凭证不会复活。需将插件升级到当前版本以获得完整连接状态和更新提示。
5. 完全退出旧客户端后用新客户端替换；不要删除客户端用户目录或 Obsidian 专用目录。

### 后续升级

升级前始终备份数据与加密密钥，停止 API 和 worker后再替换程序。插件下载新版，覆盖原 `extension` 文件夹内容并在扩展管理页点击“重新加载”，保留目录位置和原插件可保留连接设置。

客户端 V1 无自动更新；用户需下载并安装新包。网页端更新由服务维护者部署后生效；浏览器刷新即可获得新界面。

### 回退

停止 V1 服务，恢复旧程序、升级前完整数据备份及同一加密密钥后再启动。数据库有结构迁移，不能假定旧代码可以直接读取升级后的数据库。回退到旧备份会丢失备份之后的新数据，先另备份当前数据。
