# Fenext

把读到的资料，变成用得上的知识。面向应用层 AI PM 的个人知识应用。

当前发布基线为 **V1 / 1.0.0**：网页端、macOS ARM64 / Windows x64 客户端与 Chrome / Edge 插件。安装包、校验清单和发布说明见 [GitHub Releases](https://github.com/Helio-K/Fenext/releases/tag/v1.0.0)；本地构建产物生成在 `release/v1.0.0/`，不提交进 Git。微信小程序移至 `archive/miniprogram/`，属于历史实验代码，不纳入本次 V1 交付。

V1 的主场景是电脑端网站阅读：用 Chrome / Edge 中的 Fenext 插件提取当前网页，再到客户端或网页端的收集箱与知识库整理。客户端提供管理界面，浏览器插件负责读取当前页；[本机客户端实测步骤](docs/Fenext-V1-安装与部署.md#客户端-v1-实测流程)。

- [版本与文档索引](docs/Fenext-版本索引.md)
- [V1 发布说明](docs/Fenext-V1-发布说明.md)
- [V1 安装、部署与升级](docs/Fenext-V1-安装与部署.md)

客户端需连接网页服务，本次不是已经上线的公网 SaaS。未签名桌面包、Windows / Edge 待实机验收等限制见发布说明。

## 本地运行

需要 Node.js 24+。

```sh
npm install
npm run dev
```

打开 http://127.0.0.1:5173 。输入账号和密码，点击“进入知识空间”：新账号自动注册，已有账号验证密码后登录。首次注册后在设置页填入接口地址、模型名称和 API Key。也可以跳过模型设置先收集，资料将等待配置。没有预设账号或生产演示数据。

`npm run dev` 同时启动 API、worker 和 Vite。生产构建本地测试：

```sh
npm run build
npm run web
# 可选，另一个终端打开桌面客户端
npm run desktop
```

桌面默认连接 http://127.0.0.1:4310 。服务必须独立启动。远程使用环境变量 `FENEXT_APP_URL=https://你的服务域名`。本地后端随电脑关闭而停止；只有托管到独立常驻服务器后，才能做到关闭电脑后任务继续处理。

## 模型配置

目前实现 OpenAI 兼容 Chat Completions JSON 接口。默认允许：`api.openai.com`、`api.deepseek.com`、`dashscope.aliyuncs.com`；需要其他提供方时在服务端 `AI_ALLOWED_HOSTS` 中明确添加。

- 通义兼容地址示例：`https://dashscope.aliyuncs.com/compatible-mode/v1`。
- DeepSeek 兼容地址示例：`https://api.deepseek.com/v1`。
- 模型名称使用账户实际可用标识，不自动假定具备图片能力。
- 校验请求会产生少量提供方用量，成功后自动恢复等待配置的任务。
- 模型必须支持 JSON 输出；不兼容时返回可恢复错误，不退回模拟成功。
- 密钥以 AES-256-GCM 加密入库。默认本地加密密钥在 `.local/master.key`，权限 0600；数据在 `.local/fenext.sqlite`。
- 外网补充需要服务端 `TAVILY_API_KEY`。未配置时明确提示，仍可手动提交资料。

## Obsidian

桌面客户端左下角头像 → 设置与同步 → Obsidian 同步 → 连接 Obsidian。优先识别当前打开的知识库，确认后在该库内建立 `Fenext/` 专用文件夹并立即同步；用户也可选择其他 Obsidian 知识库。同步完成后，在 Obsidian 左侧打开 `Fenext/知识` 即可看到 Fenext 笔记。旧版绑定的普通目录不会自动移动或删除，需在新版中重新连接 Obsidian。

新知识写入 `知识/标题--身份前缀.md`，含稳定 `fenext_id`、版本、别名和学习等级。携带 Fenext 身份的文件可双向修改和移动；未纳管文件保持原样。冲突保留双方并产生审核入口。删除暂不传播。

同步每 30 秒检查一次，可手动触发。服务端已保存和本地已同步分别显示。可选的“导入 Fenext 文件夹中的笔记”只处理该专用文件夹内的已有 Markdown，会预览数量并在确认后纳管笔记，保留原正文和自定义 YAML 字段；不会读取知识库其他笔记。现有本地附件不自动上传。

来源、用户提交图片和问题索引会分别导出到 `来源/`、`附件/`、`问题索引/`。这些辅助文件以不可变快照创建，不覆盖用户已有文件。正文中已有的明确知识链接会转换为 Obsidian 可识别的文件链接，读取时还原语义名称，避免文件名身份后缀导致断链。Fenext 不提供独立知识图谱，也不因同一来源或同一问题自动连线；图谱展示与探索由 Obsidian 完成。

## V1 来源范围

“来源与插件”保留公开网页与论文、文字与图片、Fenext插件（Chrome / Edge）。V1 不做公众号、飞书、知乎等平台专属来源插件或公众号专属工具入口，不展示尚未接入的占位卡片。通用链接读取、正文/图片提交以及历史资料继续保留；以下公众号读取说明属于通用读取能力，不代表独立平台接入。

## 公众号验证页与手动补充

公众号链接若返回“环境异常”“完成验证后”等拦截页，读取阶段会报告来源受限，不将验证文案交给模型整理。能够读取时，优先提取公众号正文区域，并标注不包含图片内容。

历史记录中，如果唯一材料确认为公众号验证页且未产生任何知识或建议，数据库迁移会把误标的“已完成”纠正为“需要处理 / 未读到正文”。旧提取内容和模型诊断保存在检查点归档中，重试会重新读取，不能复用旧空结果。实际读取成功但没有可收录知识的任务不受影响。

在任务页点击“粘贴正文或上传截图”，在微信中打开原文、完成验证后复制正文或保存文章截图。补充表单默认勾选“链接仅作为来源记录，不读取链接”，保留原链接和问题；提交后建立新的资料任务，不修改原任务或覆盖普通收集草稿。截图最多 4 张，每张 2 MB，所选模型需支持图片输入。

接口 `/api/tasks` 可传 `urlMode: "reference"` 表示仅记录来源，必须同时提交文字或图片；省略或传 `"read"` 仍会读取链接。引用模式不向该链接发送请求，读取范围明确标记为用户提交内容，不宣称获取全文。此功能不表示已取得微信公众号平台接入权限。

## 电脑浏览器收集

Fenext插件面向桌面 Chrome 和 Microsoft Edge。网页“来源与插件 → 电脑浏览器当前页”分别列出 Chrome、Edge 下载链接，两者下载的是同一份 Chromium 插件安装包：`release/Fenext-Browser-1.0.0.zip`，尚未接入扩展商城。下载后解压，在浏览器右上角菜单进入“扩展程序/扩展 → 管理扩展程序”，开启“开发者模式”，选择“加载已解压的扩展程序”，选中解压后含 `manifest.json` 的 `extension` 文件夹。浏览器内部地址不能作为普通网页超链接打开，因此界面不再让用户复制内部地址。Edge 使用相同的 Chromium 扩展接口，目前尚未完成 Edge 实机验收；Firefox、Safari 和手机浏览器不在当前支持范围。

在 Fenext 网页的“设置与同步 → 接入与数据”填写备注并生成长期有效的接收凭证。设置页显示生成时间和服务地址；凭证仅在生成时显示一次。首次打开插件，填入服务地址和凭证，点击“连接并继续”；验证成功后会记住连接，不再显示首次引导。可以修改备注；删除凭证后插件立即失去连接，已收集资料保留。旧版仍有效的 30 天凭证迁移为长期有效，已过期的不会恢复。

打开文章网页，完成可能出现的验证，点击浏览器工具栏中的 Fenext 图标 → “提取当前页面” → 核对标题、链接和正文 → “保存并整理”。浏览器插件使用当前标签页的临时权限，保存时把提取文字作为实际材料，原链接仅作为来源记录，不再由服务端请求。若当前页是验证页或可见正文不足 80 字，插件会提示，不创建任务。远程 Fenext 服务需使用 HTTPS，并由用户授予插件连接该站点的权限。

### 插件连接状态

“来源与插件 → 电脑浏览器当前页”从服务端读取当前账号的真实连接记录，每 3 秒更新，切回页面时也会刷新。插件保存连接、打开 0.1.5 及以后版本，或成功提交资料时会确认连接；仅生成凭证不会视为已连接。凭证过期或删除后显示“凭证已失效”；Chrome 和 Edge 中仍有有效连接时保留“已连接”。此状态表示当前账号最近成功验证且凭证仍有效，不表示实时检测浏览器是否已卸载插件。

旧版没有连接记录、但提交过资料时显示“连接待确认”。无需重新安装：在旧插件的“连接设置”中保存一次，或升级后打开插件，即可确认。

### 插件更新（不接入扩展商店）

插件连接成功后，每次打开会向已连接的 Fenext 服务查询插件版本。有新版时顶部显示下载入口和折叠的更新说明；没有更新时不显示提示。底部可查看当前版本并手动检查更新。网络失败或服务尚未提供更新信息时，不影响提取与保存。

用户下载并解压新版后，用新 `extension/` 的内容覆盖原插件文件夹，然后在 Chrome 或 Edge 的扩展管理页点击“重新加载”。保持原文件夹位置、不移除原插件，浏览器会保留服务地址和接收凭证。0.1.3 及更早版本没有提醒功能，需要先手动升级一次。

发布新版：同步提升 `extension/manifest.json` 和 `extension/release-notes.json` 中的版本，填写更新说明，然后运行：

```bash
cd Fenext
npm run extension:package
```

命令生成通用 ZIP、更新清单与可供本地加载的文件夹。服务仅公布已有完整安装包的版本，并验证安装包校验和。`GET /api/integrations/extension/latest` 提供版本与更新说明；`GET /api/integrations/extension/download?version=版本号` 下载对应当前发布包，下载链接不携带用户凭证。版本检查依赖已连接的 Fenext 服务，因此发布时需将 `release/extension-update.json` 和对应 ZIP 一起部署到该服务；Docker 构建会自动打包并包含这些文件。

## 微信小程序

小程序保留通用手动收集能力。以下平台素材入口代码属于历史实验，不纳入本次 V1 交付或验收承诺。

在微信开发者工具导入 `archive/miniprogram/`，替换 `project.config.json` 中的测试 AppID。将 `archive/miniprogram/config.js` 的服务地址换成已部署 HTTPS 地址，并配置 request 合法域名。音频词典域名也需按平台规则配置。

本机地址仅用于开发者工具开发；真机不能通过 127.0.0.1 访问电脑。当前使用网页创建的个人测试账户登录，尚未接入微信/短信身份。小程序在 `app.json` 声明了网页、PNG/JPEG/WebP 图片和纯文本的聊天素材转入入口。场景 1173 下接收 `forwardMaterials` 并展示给用户确认；转入的正文或图片直接保存，链接只作来源记录。仅有链接时由服务端尝试读取，遇验证页标记为“未读到正文”。开发查询字段 `url` 和 `title` 仍可用于调试，但不等同于已获得公众号文章菜单的正式入口资格。

小程序代码尚未在微信开发者工具或真机验收；`supportedMaterials` 入口需要微信审核后才会在正式版展示。微信官方目前将该聊天素材入口的支持平台标为 Android；iPhone 可使用小程序内的手动收集页，公众号文章菜单的专属接入能力仍需另行核验。浏览器手机截图不能当作小程序验收结果。

## 托管部署

提供 `Dockerfile` 和 `compose.yaml`，API/worker 共用持久卷，适合单节点个人测试。尚未替用户购买服务或发布到云端。

1. 从 `.env.example` 创建私密配置，设置固定的 64 位十六进制 `MASTER_KEY`、高强度 `SETUP_TOKEN`、HTTPS `APP_ORIGIN`。
2. 在持久化服务器运行 `docker compose up -d --build`。
3. HTTPS 反向代理转发到服务器的 `127.0.0.1:4310`，保留 `Origin`，不要将初始化令牌写进公开页面。
4. 首个账号注册时输入管理员初始化令牌；后续新账号自动注册为独立知识空间，已有账号验证密码后登录。
5. 保留数据库和同一加密密钥，设置备份并验证恢复。不能每次部署重新生成密钥。

不要把 SQLite 放在不支持所需文件锁的网络卷，也不要横跨多台主机共用同一个文件。大规模部署需另行迁移数据库与队列。

## 备份与恢复

```sh
node scripts/backup.mjs
# 可选：指定新的备份目录
node scripts/backup.mjs /你的私密备份目录/一次备份
```

脚本使用 SQLite `VACUUM INTO` 获取一致性快照，同时备份解密所需的密钥。备份包含私人资料和密钥，不应公开。默认保留历史，不自动清理。恢复前停止 API 和 worker，保留当前数据副本，再将数据库与匹配的密钥放回配置目录；如使用 `MASTER_KEY` 环境变量，必须与备份密钥一致。恢复后启动服务并核对笔记、版本和任务。

## 外部接收接口

设置 → 接入与数据 → 生成长期有效的接收凭证，可填写备注、查看生成时间并随时删除。凭证只允许提交资料和查询单个任务，不允许读取设置、全量笔记或修改知识。

```sh
curl "$FENEXT_URL/api/tasks" \
  -H "Authorization: Bearer $FENEXT_INGEST_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: caller-stable-request-id" \
  -d '{"text":"要整理的资料","question":"希望理解什么","app":"个人收集工具"}'

curl "$FENEXT_URL/api/tasks/返回的任务标识" \
  -H "Authorization: Bearer $FENEXT_INGEST_TOKEN"
```

同一提交重试使用原幂等键；键不能复用给不同内容。相同资料与相同问题复用原任务；不同问题独立处理。收集箱按来源链接及确认过的内容归组，展开可查看各问题的时间、状态和结果。最新提问使资料排到顶部；搜索支持问题，状态筛选自动展开匹配记录。相同链接的不同正文保留为不同内容版本，原文及结果不覆盖；正文尚未读取时暂不合并，仅标题相同也不合并。任务归属从认证信息确定，忽略不可信的调用方用户编号。
